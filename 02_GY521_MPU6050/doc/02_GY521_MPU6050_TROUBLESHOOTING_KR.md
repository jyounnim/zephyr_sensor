# Lab 02 트러블슈팅 (GY-521 MPU-6050, 듀얼코어/IPM)

실기 검증 과정에서 실제로 확인한 내용만 정리했습니다.

## 1. I2C 주소 0x68/0x69 자동 감지 - 설계와 검증

**배경**: `i2c0_scanner`로 확인한 결과, GY-521의 AD0 핀을 GND(또는 미연결)로
두면 `0x68`, VCC로 두면 `0x69`로 응답함. 오버레이에 주소를 하드코딩하는 대신
두 경우 모두 코드 수정 없이 동작하도록 요구됨.

**구현 방식**: Zephyr 드라이버는 컴파일 타임에 devicetree로 디바이스 인스턴스가
고정되는 구조라 "런타임에 스캔해서 디바이스를 새로 만드는" 것은 표준적인
방법이 아닙니다. 대신 오버레이에 `mpu6050_68`(0x68)과 `mpu6050_69`(0x69) 두
노드를 모두 선언해두고, 부팅 시 실제로 `device_is_ready()`가 true인 쪽을 골라
쓰는 방식을 채택했습니다. Zephyr의 mpu6050 드라이버는 `init()`에서 WHO_AM_I
레지스터를 읽어 확인하고, 실패 시 명시적으로 에러를 반환하므로(배선 안 된
주소는 I2C 레벨에서 NACK), 이 성질을 그대로 이용한 것입니다.

**경쟁 상태(race condition) 방지**: 디바이스 선택 로직(`mpu6050_select()`)은
`main()`이 아니라 `mpu6050_thread` 스레드 자신의 시작 부분에서 실행됩니다.
`K_THREAD_DEFINE`로 등록된 스레드(지연 0ms)는 `main()`보다 먼저 스케줄될 수도
있어서, `main()`에서 고른 디바이스 포인터를 스레드가 나중에 참조하는 구조였다면
아직 선택되지 않은 `NULL` 포인터로 `sensor_sample_fetch()`를 호출하는 경쟁
상태가 생길 수 있었습니다 - 선택 로직을 스레드 자신의 진입부로 옮겨 이 문제를
원천 차단했습니다.

**✅ 실기 검증 완료**: 부팅 로그에서 다음 순서를 확인함:
```
[00:00:00.225,000] <err> MPU6050: Failed to read chip ID.
*** Booting Zephyr OS build v4.4.0 ***
[00:00:00.226,000] <inf> app_procpu: 02_GY521_MPU6050 (core0/procpu) starting
[00:00:00.231,000] <inf> app_procpu: MPU6050 found at 0x68 (AD0 low/floating)
```
`Failed to read chip ID.` 에러는 배선 안 된 0x69 노드의 `init()`이 커널 부팅
단계(애플리케이션 `main()`보다 먼저)에서 자동 실행되며 WHO_AM_I 읽기에
실패한 것으로, **의도된 정상 동작**임을 확인했습니다. 그 직후
`mpu6050_select()`가 0x68을 올바르게 골라냈습니다. 부팅 시간에 눈에 띄는
지연도 없었습니다(0.225초~0.231초 사이).

**참고**: 이 에러 로그 자체가 거슬린다면, MPU6050 모듈만 로그 레벨을 낮춰
조용히 만들 수 있습니다(기능에는 영향 없음). 정확한 Kconfig 심볼명은 Zephyr
버전에 따라 다를 수 있으므로 `west build -t guiconfig`에서 "MPU6050" 검색해
확인할 것.

**검토했으나 채택하지 않은 대안**: `i2c0_scanner`처럼 raw I2C write/read로
직접 주소를 프로빙한 뒤 분기하는 방식도 가능했지만, 그러면 Zephyr 표준 센서
드라이버(`sensor_sample_fetch`/`sensor_channel_get`)를 포기하고 MPU6050
레지스터 프로토콜을 직접 구현해야 해서 훨씬 번거로움. 두 devicetree 노드를
미리 선언해두고 드라이버의 자체 초기화 실패를 감지 신호로 쓰는 방식이 표준
API를 그대로 유지하면서 훨씬 적은 코드로 같은 목적을 달성함.

## 2. Lab 01에서 이어받아 그대로 적용한 예방 조치

Lab 01에서 실기로 확인된 이슈들을 이 랩에서는 처음부터 반영해 재발을
방지했습니다:
- **sysbuild + MCUboot**: `lab/sysbuild.conf`에 `SB_CONFIG_BOOTLOADER_NONE=y`
  (Espressif 보드가 `--sysbuild` 시 기본으로 MCUboot를 끼워 넣으려는 문제)
- **IPM Kconfig 심볼명**: `CONFIG_ESP32_SOFT_IPM=y` 사용 (`CONFIG_IPM_ESP32`
  아님)
- **폰트 글리프 누락 주의**: 화면에 쓰는 모든 라벨 문자가 `font5x7.h`에
  있는지 미리 확인 - 이 랩은 AX/AY/AZ/GX/GY/GZ/TEMP 라벨에 필요한 'X', 'Z'를
  처음부터 추가해뒀고, 실기에서 화면이 정상 출력되는 것으로 확인됨
- **새 I2C 디바이스는 배선 직후 스캐너부터**: 이 랩은 주소 자동 감지 덕분에
  필수는 아니었지만 관례는 유지

## 3. 화면 표시 단위(g, deg/s) 추가는 보류

가속도 값에 'g' 단위를 붙이는 걸 검토했으나(폰트에 소문자 'g' 추가까지 완료),
최종적으로 보류하기로 함 - 화면이 더 지저분해 보인다는 판단. 폰트에서 미사용
'g' 글리프는 정리해 최소 세트로 되돌림. 필요해지면 언제든 다시 추가 가능
(설계 문서 "확장 아이디어" 참고).
